# 产品需求文档 (PRD) —— 本地 AI 隐私安全网关 (GuardAgent)

## 1. 文档概述

### 1.1 产品背景

随着 Cursor、Claude Code、Aider 等 AI 编码智能体（Coding Agents）在日常开发中的普及，越来越多的程序员选择通过 AI 挂机、长文本分析等方式来提升编码效率。然而，许多高安全性行业（如金融、跨境电商、医疗、国企）对代码资产和数据合规有极高要求。这些企业严禁员工将包含敏感配置（如生产环境 API 密钥、内网 IP 地址、数据库账号密码、员工姓名等）的源码上传到云端大模型中，违者面临被 IT 部门审计、约谈或解雇的风险。

### 1.2 产品定位与核心目标

* **产品名称：** GuardAgent / SpecShield (暂定)
* **技术选型：** TypeScript (TS) + Tauri 2.0 + Fastify (Node.js/Bun Sidecar 辅助进程)
* **产品形态：** 跨平台本地桌面客户端（macOS / Windows）。
* **核心口号：** “把代码交给 AI，把秘密留在本地。”
* **核心目标：** 为独立程序员打造一个**本地运行、超低延迟、零配置**的隐形隐私网关。通过拦截本地 AI 工具发出的 HTTP 请求，在本地将代码中的敏感信息替换为安全占位符，并在大模型流式（Stream）返回结果时瞬间还原，确保 AI 既能正常理解代码逻辑并产出正确解答，又不会获取到任何真实敏感数据。

---

## 2. 目标用户与核心痛点

### 2.1 目标用户

* 在具有严厉合规、网络安全审查限制的公司（金融、证券、跨国大厂、医疗卫生）工作的开发者。
* 重度依赖 Cursor、Claude Code 等 Agent 化编码工具，且经常需要 AI 阅读复杂本地上下文的程序员。

### 2.2 核心痛点

* **合规翻车风险：** 程序员在让 AI 重构代码或编写测试时，容易由于手快而将带有内网 IP、测试环境数据库密码或第三方 API Token 的文件直接发给 AI。
* **手动脱敏低效：** 在使用 AI 前，频繁需要手动把代码中的 `192.168.x.x` 改为 `xxx`，或将真实的密码隐藏，聊完后再手动改回来，极大破坏了开发的流畅度。
* **市面方案太重：** 企业级的数据泄露保护（DLP）系统和安全网关配置极其复杂、费用高昂，且往往缺乏大模型特定的流式传输还原闭环，容易导致 AI 工具直接卡死或给出损坏的代码。

---

## 3. 系统核心架构与数据流

为了确保在本地以极致性能运行，系统采用 **前端 UI 层** 与 **底层代理服务（Sidecar 辅助进程）** 相互解耦的架构：

1. **前端 UI 层 (Tauri + Vite + React/Vue + TS)：** 负责本地运行开关、规则库配置管理、实时拦截与脱敏流水日志展示。
2. **代理服务层 (Fastify + TS + Node.js/Bun)：** 常驻本地一个未占用的端口（例如 `http://localhost:9999`），专门模拟大模型厂商的 API 中转站。

### 3.1 核心数据闭环流程图

```
[ Cursor / Claude Code ] 
       │
       │ ① 发送带有敏感信息的 Prompt & 源码文件
       ▼
[ GuardAgent 本地代理 (Fastify/TS) ] ──► ② 毫秒级正则扫描，生成并记录内存字典 (Mapping Table)
       │                              ③ 将文本中的敏感部分安全替换为 [GUARD_XXX] 占位符
       │ ④ 转发脱敏后的安全代码
       ▼
[ 云端大模型 (OpenAI / Anthropic) ]
       │
       │ ⑤ 异步流式返回（SSE Stream 逐字打字机效果）
       ▼
[ GuardAgent 本地代理 (Fastify/TS) ] ──► ⑥ 监控「滑动窗口缓冲区」，防范占位符碎片横向切断
       │                              ⑦ 识别占位符，查反向字典，实时替换复原为真实信息
       │ ⑧ 输出 100% 还原、可直接运行的完整代码
       ▼
[ Cursor / Claude Code ] (无感接收，代码高亮直接采纳)

```

## 4. 核心功能需求 (Functional Requirements)

### 模块一：本地网络代理与“无感拦截” (Proxy & Interception)

* **FR-1.1 协议深度模拟：** 代理服务层必须完美对接各大模型的标准 HTTP 协议结构，重点适配 OpenAI (`/v1/chat/completions`) 以及 Anthropic (`/v1/messages`) 的入参及出参定义。
* **FR-1.2 预检与鉴权透传：**
* 正确响应 Cursor 等客户端发起的 HTTP `OPTIONS` 跨域预检请求。
* 将请求头中的 `Authorization` (包含真实的大模型 API Key) 安全透传转发至云端，本地不做拦截存储。


* **FR-1.3 SSE (Server-Sent Events) 转换转发：** 完美适配流式传输响应。代理服务器必须通过 TypeScript 异步迭代器（如 `for await...of`），以 `chunk` 为单位接收云端响应、处理响应并流式吐给 Cursor。

### 模块二：基于 TS Regex 的敏捷脱敏引擎 (Anonymize Engine)

在请求发往云端之前，引擎拦截 `body.messages` 或对应的 Prompt 文本。必须在 V8 引擎底层支持下，通过极速的 TypeScript 正则表达式库解决程序员最痛的 80% 高频场景。

* **FR-2.1 Secrets 凭证防漏：**
* **匹配策略：** 正则检测常见模型 Key 格式（例如 `/(sk-[a-zA-Z0-9]{48})/g`），以及常见的明文变量赋值模式（如 `password\s*:\s*['"][^'"]+['"]`，`AWS_SECRET_ACCESS_KEY` 等）。
* **占位符命名：** `[GUARD_SECRET_${index}]`


* **FR-2.2 网络环境信息（IP/Domain）：**
* **匹配策略：** 严格匹配 IPv4 地址（排除公网开源 CDN 节点）、内网常见网段（`192.168.x.x`, `10.x.x.x`, `172.16.x.x`）及本网段后缀（`*.local`, `*.internal`, `localhost`）。
* **占位符命名：** `[GUARD_IP_${index}]`


* **FR-2.3 数据库敏感连接串：**
* **匹配策略：** 捕获形如 `mysql://username:password@hostname:port/db` 的连接。
* **行为：** 仅针对 `username:password` 部分进行脱敏，**必须保留协议头和端口**（例如替换为 `mysql://[GUARD_DB_CREDS_1]@hostname:port/db`），确保大模型能够理解当前代码所用的数据库类型，不破坏 AI 对语法的认知。


* **FR-2.4 员工信息与注释隐私 (PII)：**
* **匹配策略：** 正则捕获代码注释中常见的 `@author 张三`、`Modified by John` 结构。
* **占位符命名：** `[GUARD_NAME_${index}]`



### 模块三：双向时空映射矩阵与请求生命周期 (Mapping & Lifecycle)

* **FR-3.1 Scoped 独立请求字典：** 每次 HTTP 请求到达代理时，在内存中为该请求单独实例化一个唯一的上下文映射表，防止多个 Cursor 窗口或并发请求之间的数据交叉错乱。
```typescript
interface ScopedContext {
  requestId: string;
  anonymizeMap: Map<string, string>;   // 示例: "[GUARD_IP_1]" -> "192.168.1.100"
  deanonymizeMap: Map<string, string>; // 反向映射，加速还原替换
}

```


* **FR-3.2 内存即用即刷 (GC)：** 一旦请求流结束（`Stream end / close`）或被客户端主动取消（`Abort`），该请求生命周期对应的 `ScopedContext` 必须立即执行 `.clear()` 并在运行内存中销毁，严防内存溢出（OOM）。

### 模块四：流式碎片缓冲区（Stream Slider Buffer）

* **FR-4.1 占位符边界切断防漏（核心难点）：** 由于大模型返回的是 SSE 流切片（Chunk），大模型在吐出占位符时，存在极大概率把一个完整的占位符横向切断分批吐出。
* *例如：* Chunk 1 返回了 `The server ip is [GUARD_`，Chunk 2 返回了 `IP_1]. Please check.`。
* 如果网关不做控制，直接将 Chunk 1 传给客户端，由于其没有匹配到完整占位符，将导致复原失败，客户端最终会显示损坏的代码。


* **FR-4.2 滑动窗口设计需求：**
* TS 代理层必须实现一个大小上限为 30 字节的自定义 **滑动窗口缓冲区 (Sliding Window Buffer)**。
* 当检测到当前接收的字符串块末尾包含 `[` 或 `[G`、`[GUARD_` 等符合占位符特征的前缀且不带闭合括号 `]` 时，该段文本必须**暂扣留**在缓冲区中。
* 待下一个 Chunk 到达后拼接完毕、完成反向查找还原后，再统一拼装发送给 Cursor。



### 模块五：桌面客户端 UI 界面 (Desktop App View)

* **FR-5.1 一键总控开关：** 界面主区域提供一个明显的 “隐私盾牌已开启 / 已暂停” 的大开关。
* **FR-5.2 配置辅助指引：** 针对常用开发工具提供一键复制配置文本的交互卡片。
* Cursor 用户：生成 `Override OpenAI/Anthropic Base URL: http://localhost:9999/v1`
* Claude Code 用户：提供终端导出命令：`export ANTHROPIC_BASE_URL=http://localhost:9999/v1`


* **FR-5.3 拦截流水日志瀑布流：** 当底层 Sidecar 替换敏感词时，通过 Tauri 的事件机制 (`window.emit`) 实时将事件泵送到前端。前端使用流水日志动画（如：`[12:01:23] 成功拦截生产环境 AWS_KEY 并进行了防外泄脱敏`），给开发者直观的安全获得感。

## 5. 非功能需求 (Non-Functional Requirements)

* **NFR-5.1 极致超低延迟（核心性能指标）：**
* 在文本脱敏阶段，50,000 字（约一大型代码文件上下文）的正则匹配与占位符生成耗时必须控制在 **5ms 以内**。
* 在大模型返回流的还原阶段，单次 Chunk 的字符串搜索替换耗时必须 **$\le$ 1ms**。必须保证打字机（流式）动画绝对无肉眼可见的卡顿或黏连现象。


* **NFR-5.2 零数据外流与本地优先：**
* 应用严禁收集、存储任何用户审查的代码片段、映射表字典。
* 映射表必须且只能保存在内存（RAM）中，禁止持久化到本地硬盘（如 `localStorage`、`SQLite` 文件等），应用一旦关闭，所有映射数据全部在物理层面抹除。


* **NFR-5.3 轻量化占用：** * 借助 Tauri 的底层原生渲染，整体应用运行内存占用保持在 150MB 以下，安装包体积保持在 20MB 以内，避免给开发者的主工作机造成性能负担。

## 6. 产品 MVP 落地迭代规划 (Roadmap)

### Phase 1：核心骨架与链路验证 (第 1 - 2 周)

* 使用 TypeScript 搭建本地 Fastify 代理层，跑通对 Cursor 的标准 OpenAI 协议（`/v1/chat/completions`）代理转发。
* 实现对 **API Key** 以及 **标准内网 IP** 的 Regex 拦截脱敏以及响应流的还原逻辑。

### Phase 2：桌面客户端打包与核心优化 (第 3 - 4 周)

* 引入 Tauri 2.0，编写一键开关和极简的引导页面、实时拦截日志视图。
* 编写**滑动窗口缓冲区**逻辑，修复占位符被 Chunk 横向切碎时无法复原的代码损毁 Bug。
* 补全对 **数据库长连接串** 和 **注释人名** 的脱敏规则。

### Phase 3：高级自定义与生态兼容 (未来展望)

* 开放“自定义高级黑名单”功能：允许程序员自己输入特定的企业内部保密项目代号（如 `Project_Apollo`）或特定内部域名，自定义正则将其纳入加密范围。
