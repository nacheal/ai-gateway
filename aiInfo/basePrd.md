# 小红书写作助手 — 产品需求文档

**版本:** v1.0  
**日期:** 2026-05-25  
**作者:** 待填写

---

## 1. 产品概述

### 1.1 产品定位

一款面向小红书内容创作者的 AI 写作辅助工具。用户提供自己的草稿和参考的热门帖子，AI 自动拆解热门帖子的写作套路，并引导用户分步选择风格，最终生成一篇优化后的小红书帖子。

### 1.2 目标用户

- 有内容创作需求但写作能力有限的普通用户
- 希望提升帖子质量和互动率的小红书博主
- 运营人员、品牌方需要批量产出小红书内容

### 1.3 核心价值

- 降低内容创作门槛，让普通人也能写出爆款风格的帖子
- 通过真实热门案例学习，而非模板化输出
- 分步参与式交互，用户对结果有掌控感，认同度更高

---

## 2. 用户旅程

```
Step 1：输入
  用户填写自己的草稿 + 粘贴 3 篇热门参考帖子

Step 2：AI 拆解
  AI 分析 3 篇热门帖子，提炼：
  - 标题套路（各篇分别展示）
  - 开头钩子类型
  - 内容结构
  - 表情/排版风格
  - 话题标签策略

Step 3：用户选择
  用户从拆解结果中主动选择：
  - 用哪种标题风格
  - 用哪种开头方式
  - 用哪种内容结构

Step 4：AI 改写
  基于用户草稿 + 用户选择的套路，生成最终版本
  用户可一键复制
```

## 3. 功能需求

### 3.1 Step 1 — 输入页

| 字段 | 说明 | 是否必填 |
|---|---|---|
| 我的草稿 | 用户自己写的原始内容，可以很粗糙 | 是 |
| 热门帖子 1 | 复制粘贴的热门小红书原文 | 是 |
| 热门帖子 2 | 同上 | 否 |
| 热门帖子 3 | 同上 | 否 |

**交互要求：**
- 草稿输入框不限字数，placeholder 提示"随便写，哪怕几个关键词也行"
- 至少填写 1 篇热门帖子才能进入下一步
- 提交时展示 loading 状态，流式输出拆解结果

### 3.2 Step 2 — 拆解展示页

AI 对每篇热门帖子输出以下维度的拆解：

| 维度 | 说明 | 示例 |
|---|---|---|
| 标题套路 | 标题用了什么吸引眼球的技巧 | 数字型："5个让你瞬间好看的技巧" |
| 开头钩子 | 第一句话如何抓住读者 | 痛点型："每次出门都不知道穿什么？" |
| 内容结构 | 帖子整体是怎么展开的 | 问题→原因→解决方案→总结 |
| 表情风格 | 表情符号的密度和使用位置 | 每段开头一个，结尾密集 |
| 标签策略 | 话题标签的数量和类型 | 3个大标签 + 2个精准小标签 |

**交互要求：**
- 每篇帖子的拆解用卡片展示，视觉上区分
- 拆解内容流式输出，逐字呈现，避免白屏等待感
- 拆解完成后自动出现"开始选择套路"按钮

### 3.3 Step 3 — 套路选择页

用户在以下三个维度各选一个选项：

**标题风格（单选）**
- 从 3 篇拆解结果中各提取 1 种，共 3 个选项
- 每个选项展示：套路名称 + 示例标题

**开头方式（单选）**
- 同上，3 个选项
- 每个选项展示：类型名称 + 示例句子

**内容结构（单选）**
- 同上，3 个选项
- 每个选项展示：结构名称 + 简要说明

**交互要求：**
- 选项用卡片形式展示，点击选中高亮
- 三个维度全部选择后，"生成我的帖子"按钮激活
- 支持返回上一步重新查看拆解

### 3.4 Step 4 — 改写输出页

AI 基于以下输入生成最终帖子：
- 用户原始草稿
- 用户选择的标题风格、开头方式、内容结构
- 原帖子的表情风格和标签策略（自动沿用，不需用户选）

**输出格式：**
```
【标题】
（正文，包含表情符号）
（话题标签）
```

**交互要求：**
- 流式输出，字符逐步呈现
- 提供"一键复制全文"按钮
- 提供"重新生成"按钮（保持相同选择重新生成）
- 提供"返回修改选择"按钮
- 复制成功后有短暂的视觉反馈（"已复制"提示）

## 4. 非功能需求

### 4.1 性能
- Step 2 拆解：首字符出现时间 < 3 秒
- Step 4 生成：首字符出现时间 < 3 秒
- 全程使用流式输出，禁止整块等待

### 4.2 兼容性
- 支持桌面端 Chrome / Safari / Edge 最新版
- 移动端支持基本浏览（输入体验不作为 v1 优先项）

### 4.3 数据安全
- v1 不存储任何用户输入内容
- API Key 不暴露在前端（通过后端代理调用，或使用环境变量）

## 5. 技术方案

### 5.1 技术栈

| 层级 | 技术选型 |
|---|---|
| 前端框架 | React + Tailwind CSS |
| AI 调用 | DeepSeek API（deepseek-chat） |
| 流式输出 | Fetch API + ReadableStream |
| 部署 | Vercel（前端）/ 无后端 |

### 5.2 Prompt 设计（核心）

**Step 2 拆解 Prompt 结构：**
```
系统角色：你是一位小红书爆款内容分析专家
任务：分析以下 {N} 篇热门小红书帖子，分别提炼每篇的：
  1. 标题套路（套路名 + 一句话解释）
  2. 开头钩子（类型 + 原文第一句）
  3. 内容结构（用箭头表示流程）
  4. 表情风格（密度 + 位置规律）
  5. 标签策略（数量 + 类型组合）
输出格式：JSON，便于前端渲染
```

**Step 4 改写 Prompt 结构：**
```
系统角色：你是一位擅长小红书写作的内容创作者
任务：将用户的草稿改写为一篇小红书帖子
约束：
  - 标题风格：{用户选择}
  - 开头方式：{用户选择}
  - 内容结构：{用户选择}
  - 保留草稿的核心信息和个人观点
  - 加入适量表情符号，风格参考：{拆解结果}
  - 末尾添加 3-5 个话题标签
```

### 5.3 状态管理

```
全局状态：
  - currentStep: 1 | 2 | 3 | 4
  - userDraft: string
  - referenceArticles: string[]
  - analysisResult: AnalysisResult | null
  - userChoices: { titleStyle, openingStyle, structureStyle }
  - finalOutput: string
```

## 6. 界面设计要求

- 风格：简洁、现代，符合年轻用户审美
- 步骤进度：顶部显示 Step 1/2/3/4 进度条
- 配色：以白色为主，粉色/珊瑚色作为主题色（贴合小红书品牌感）
- 字体：正文清晰易读，标题有设计感
- 动效：步骤切换有过渡动画，流式输出有光标闪烁效果

## 7. 开发阶段规划

### Phase 1（1-2 天）：核心跑通
- [ ] 搭建 React 项目基础结构
- [ ] 实现 Step 1 输入表单
- [ ] 接通 DeepSeek API，实现流式输出
- [ ] 完成 Step 2 拆解展示（纯文本版）

### Phase 2（3-5 天）：体验完善
- [ ] Step 3 选择交互（卡片选择 UI）
- [ ] Step 4 改写输出 + 一键复制
- [ ] 步骤进度条
- [ ] 错误处理和 loading 状态

### Phase 3（1 周后）：功能增强
- [ ] 拆解结果结构化展示（JSON → 卡片渲染）
- [ ] 历史记录（localStorage）
- [ ] 一次生成多个标题供选择
- [ ] 移动端适配

## 8. 成功指标

| 指标 | 目标 |
|---|---|
| 完整走完 4 个步骤的转化率 | > 60% |
| 用户复制最终结果的比例 | > 40% |
| 平均单次使用时长 | 3-8 分钟 |
| 用户反馈"结果比自己写的好" | > 70% |
